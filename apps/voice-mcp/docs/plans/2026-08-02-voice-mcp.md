# voice-mcp: agent-initiated real-time phone calls (MCP + telephony gateway)

## Purpose

An MCP host (Claude Code, Codex, or any stdio-capable client) can place a real
phone call to an allowlisted person and hold a natural, interruptible spoken
conversation driven by an OpenRouter-hosted LLM, with ElevenLabs voice over
Twilio ConversationRelay. An operator observes: `voice-mcp doctor` all-green;
`voice-mcp serve` running with a public tunnel URL; an MCP client calling
`voice_prepare_call` → `voice_start_call` places a call whose transcript,
events, and (policy-permitting) encrypted recording are findable afterwards via
`voice_get_transcript` / `voice_search_calls` and the `voice-mcp` CLI.

Selected v1 architecture (user-approved spec, 2026-08-02):

`MCP host → voice-mcp → Twilio ConversationRelay → OpenRouter LLM →
ElevenLabs voice through Twilio → phone`

Naming (user instruction 2026-08-02): the tool is **voice-mcp** —
`apps/voice-mcp`, package `@george43g/voice-mcp`, CLI `voice-mcp`. MCP tool
names keep the `voice_*` prefix from the spec.

## Context and boundaries

- ConversationRelay provides managed STT/TTS/interruption/token streaming
  while we keep the LLM, history, and observability. Raw bidirectional Media
  Streams stay a measured escape hatch only (8 kHz μ-law, codec/turn-taking
  work) — do not switch without latency evidence.
- OpenRouter is the v1 LLM via an OpenAI-compatible streaming adapter; moving
  to Ollama is a config change (`baseUrl: http://localhost:11434/v1`, local
  model, no key). The initiating agent supplies an objective and optional
  context; the OpenRouter model conducts the conversation.
- ElevenLabs' own MCP exposes managed-agent outbound calls, but a custom
  service is warranted for: selectable LLM, live observability, local
  indexing, recording policy, provider abstraction.
- Three entrypoints over shared domain services: `voice-mcp mcp` (stdio MCP,
  stderr-only logging), `voice-mcp serve` (public Twilio webhook/WS listener +
  separate localhost-only admin/observability listener), `voice-mcp` CLI
  (`doctor`, `prepare`, `call`, `watch`, `recording play|export|delete`,
  `history`).
- Explicit ports: `TelephonyAdapter` (v1: `twilio-conversation-relay`),
  `LlmAdapter` (v1: `openai-compatible`), `EventStore`, `RecordingStore`,
  `SecretProvider`, clock + ID providers. Config identifiers
  `elevenlabs-managed` and `twilio-media-streams` are reserved, not
  implemented.
- State: `~/Library/Application Support/voice-mcp` (0700) — node:sqlite WAL
  DB (calls, append-only events, utterances, recording metadata, timings) +
  FTS5 transcript index (Node 24 `node:sqlite` FTS5 verified locally).
  Config: `~/.config/voice-mcp/config.json` (strictly zod-validated; env
  overrides `VOICE_MCP_CONFIG` / `VOICE_MCP_STATE_DIR` for tests).
- Secrets resolve lazily by variable name: process env first, then the opkeep
  keychain cache (`security find-generic-password -s dotfiles -a VAR -w`).
  [Update 2026-08-16: opkeep re-keyed its cache service to `opkeep` on
  2026-08-06; the provider default now follows it — see `src/stores/secrets.ts`.]
  Never commit `.env`, secret values, full phone numbers, or tunnel URLs.
  Registry vars in play: `TWILIO_ACCOUNT_SID`, `TWILIO_API_KEY`,
  `TWILIO_API_SECRET`, `TWILIO_AUTH_TOKEN` (signatures),
  `OPENROUTER_API_KEY`.
- Safety invariants (tested): allowlisted recipients only (E.164 in config,
  last-four elsewhere); `recordingPolicy: preconsented | manual | never`;
  disclosure audio/text NEVER plays automatically; recording never auto-starts
  for `manual`, never possible for `never`; two-stage
  `voice_prepare_call` (expiring request) → `voice_start_call` (explicit
  confirmation, marked paid/destructive/non-idempotent/open-world; retries
  return the already-created call); recordings AES-256-GCM-encrypted with a
  macOS-Keychain-held key; playback decrypts to a private temp file and
  removes it after.
- Twilio boundary hardening: validate every HTTP + WS request signature
  (HMAC-SHA1, timing-safe); reject replayed callbacks (provider-key dedup),
  unknown Call SIDs, out-of-order status downgrades; admin routes never on
  the public listener; `publicBaseUrl` required at startup.
- Authority boundaries: NO commits/pushes, NO global software installs
  (Cloudflare Quick Tunnel client needs explicit approval), NO live/paid
  calls in this pass. The paid smoke call (latency targets p50 ≤ 1.0 s /
  p95 ≤ 1.5 s end-of-turn→first-audio over ≥20 turns, barge-in stop ≤500 ms)
  is a separately authorized step after ConversationRelay account eligibility
  is confirmed. If ConversationRelay is unavailable on the account, stop and
  report — no silent fallback to ElevenLabs-managed calls. Preserve the
  shared worktree's unrelated changes.

## Discoveries

- The scaffolder's full output (TUI/ink, vite, rust-accel, HTTP transport) is
  far larger than this service needs, and `mcp-scaffold add-mcp-app` has live
  preconditions that reject this repo's app naming — patterns reused
  selectively instead (tool-definition registry, commander, strict zod,
  stderr-only MCP logging).
- Twilio credentials (2026-08-02): the keychain-cached TWILIO_ACCOUNT_SID /
  TWILIO_AUTH_TOKEN (from op item `twilio-au1-live`) return 401 against both
  api.twilio.com and api.au1.twilio.com — stale. The working live account is
  op item `twilio-us1-live` ("MWC Billing & AI", Full/active, one
  voice-capable AU number …1463, AU low-risk dialing enabled). No API key
  (SK…) pair exists in op; the smoke test aliased account SID + auth token as
  TWILIO_API_KEY/TWILIO_API_SECRET via env in the serve shell (Twilio REST
  accepts that basic-auth pair). opkeep's dotfiles templates still map
  TWILIO_* to `twilio-au1-live` — worth repointing or rotating.
  [Update 2026-08-16: repointed to `twilio-us1-live` and the AU1 items
  archived by the life-stack session. Later same day: an `SK…` key existed
  all along (twilio-cli mint, 2026-05-13) — now 1P item `TWILIO_API_KEY`;
  secret pending rotation after a transcript leak. See HANDOFF § Operational
  gotchas for the API-key-401-on-Account-resource health-check trap.]
- ConversationRelay works on the account without extra console enablement:
  ElevenLabs TTS (premade voice Charlie IKne3meq5aSn9XLyUdCD), en-AU, and
  Deepgram Flux STT all accepted. Error 64101 with a `block_elevenlabs/…`
  message text is what an invalid ElevenLabs settings string produces — it
  does NOT mean the provider is account-blocked; bare-integer speed was the
  trigger. Calling the account's own Twilio number (answers with Twilio's
  demo message) is a ~zero-risk way to validate TwiML/TTS config on a real
  answered call without ringing a human.
- Quick Tunnel URLs are per-process: restarting cloudflared mints a new
  `*.trycloudflare.com` host, so `server.publicBaseUrl` in
  `~/.config/voice-mcp/config.json` must be updated and `serve` restarted
  together.

## Decisions

- All mutations (prepare/start/end/disclosure/set-recording/delete) go
  through the serve process's localhost admin API; MCP + CLI read history
  directly from sqlite read-only. Rationale: single WAL writer, one place for
  concurrency caps and live session handles; MCP works against a running
  gateway or fails with a clear "gateway not running" error. (2026-08-02)
- Build with plain `tsc` to `dist/` (repo runs from source via `tsx`; no vite
  bundling needed for a local service). (2026-08-02)
- Local MCP consumers poll event cursors/resources; public Streamable HTTP
  MCP with OAuth is explicitly deferred. (spec)
- Default voice: ElevenLabs Flash via ConversationRelay, en-AU, Deepgram Flux
  STT (Google STT retained as configurable alternative for Melbourne latency
  comparison). Defaults: one concurrent call, 15-minute cap, both
  configurable under administrator caps. (spec)
